# Divergences from ext-mongodb 2.5.6

This driver aims at exact parity with ext-mongodb 2.5.6 (libmongoc/libbson 2.5.8). The rule is:
**safety beats parity.** Where mirroring the reference would crash, read freed memory, send on a
socket inherited across `fork()`, overflow, allocate without bound or let server data control
something it should not, this driver does the closest safe thing instead. It throws the nearest
matching exception rather than crashing, and refuses rather than silently proceeding.

This file lists every known difference. Each entry gives the reference behaviour, ours, the reason,
and the test that pins ours (PHPT under `tests/local/`, or a `cargo test` in `crates/core`).
Upstream tests that fail because of an entry are named with it. `tests/NOT_APPLICABLE.md` lists the
tests that cannot run here.

## 1. Permanent, for safety

| Area | Reference (ext-mongodb 2.5.6) | This driver | Why | Pinned by |
|---|---|---|---|---|

| Credentials in debug output and URI errors | `var_dump($manager)` (`uri`) and the "Failed to parse MongoDB URI: '...'" message show the URI as given, password included; a %-decoding error quotes the option's value | the password, the values of `tlsCertificateKeyFilePassword` and `sslClientCertificateKeyPassword`, and an `authMechanismProperties` value with any secret property (such as `AWS_SESSION_TOKEN`) are replaced by `******`; the username is kept. | Unescaped `@` in the userinfo (`mongodb://user:p@ss@host/`) | the URI is split at the first `@`: the rest of the password becomes part of a host name (resolved through DNS, shown in errors and server descriptions) | `InvalidArgumentException` "Failed to parse MongoDB URI: ... ("Username ..." without a `:`), the message libmongoc gives for the other unescaped characters | a password fragment must not reach DNS, logs or debug output | `tests/local/manager-redact-001.phpt`, `cargo test redacts_secrets` |
| SCRAM iteration count from the server | any count of at least 4096 (parsed into a C `int`: counts above 2^31 wrap around) | at least 4096 and at most 10,000,000, else `RuntimeException` "SCRAM Failure: iterations must be at most 10000000" (MongoDB's defaults are 10,000 and 15,000) | the server would choose how long PBKDF2 keeps the client busy | `cargo test step2_errors` |
| SCRAM `i=` value that does not start with a digit or sign | libmongoc reads an uninitialised end pointer (undefined behaviour) | `RuntimeException` "SCRAM Failure: unable to parse iterations in sasl step2" | memory safety | `cargo test step2_errors` |
| Reference cycles through subscribers (a subscriber that keeps its `Manager`, or a `Server`, `Cursor`, `Session` or `WriteResult` of it) | none of these references is reported to the garbage collector: the cycle is never collected and lives until the end of the request; when it holds a `Cursor` (for instance the result of `executeCommand()`), the process crashes at shutdown (SIGSEGV) | `get_gc` reports the subscribers of a `Manager` and the `Manager` (and the other PHP values) held by a `Server`, `Cursor`, `Session` or `WriteResult`, so such a cycle is collected. While the collector frees it, no subscriber is called (they may belong to the cycle and be freed already; a subscriber storing `$this` would otherwise keep freed memory): the events stay queued, and those of a `disableClientPersistence` client freed with the cycle are not delivered (`endSessions` is still sent; its command events and `topologyClosed` are not seen). Dispatch also skips any subscriber object the collector has freed. Without the collector (`zend.enable_gc=0`) the cycle is freed at shutdown without a crash | crash at shutdown; unbounded memory in long-running workers | `tests/local/manager-gc-cycle-001.phpt` (the reference fails it: nothing collected, then SIGSEGV) |
| Compressed replies (OP_COMPRESSED) | the declared uncompressed size must fit `maxMessageSizeBytes` and match what the data decompresses to ("could not decompress message from server"); the codecs decompress into a buffer of the declared size | the same checks and message; decompression stops one byte past the declared size (a stream that produces more is refused without producing the rest), the limit is the bounded one of "Wire replies" above, a snappy block whose own length header differs from the declared size is refused before decoding, and a zstd frame may not ask for a window larger than the power of two that covers the declared size (at least 1 MiB) | a server must not make the client allocate or work without bound | `cargo test compress::` (`sizes_are_exact_and_bounded`, `op_compressed_messages`) |
| DNS answers for `mongodb+srv://` (SRV and TXT records) | libresolv's parser (res_nsearch, ns_parserr, dn_expand) bounds names and records; libmongoc reads an SRV record's port without checking the record's length; any number of records is accepted | the same lookups and messages through a Rust stub resolver: a response is at most 65,535 bytes, a reply counts only when its ID, flags and question match the query (UDP datagrams from other addresses are dropped by a connected socket), names are decompressed with strictly backward pointers into at most 255 octets, every record must lie inside the message, an SRV record shorter than its fixed fields plus a target is refused ("Invalid record in SRV answer for ..."), and an answer with more than 1,024 records is refused ("Too many records in SRV answer for "...": at most 1024 are accepted") | a DNS server, or something answering in its place, must not make the client read out of bounds, loop or allocate without bound | `cargo test dns::`, `cargo test srv::` |
| `BulkWriteCommand` batches when the server reports `maxWriteBatchSize` 0 (or less) | libmongoc's batch loop adds no operation and sends empty `bulkWrite` batches forever | at least one operation per batch; the other limits (`maxMessageSizeBytes`, the per-document error) are unchanged | a server must not hold the client in an endless loop | `cargo test batch_progress_with_zero_max_batch` |
| `BulkWriteCommand` results cursor | every result document the cursor yields is applied, and `getMore` is sent as long as the server returns a non-zero cursor id | at most one result per operation of the batch and at most that many `getMore` round trips; beyond that the batch fails as libmongoc fails on a malformed result (`InvalidArgumentException` "bulk write returned more than N results for N operations" or "bulk write results cursor needed more than N getMore commands for N operations", wrapped in a `BulkWriteCommandException` when there is a partial result), and the cursor is killed. A result index outside the batch is refused as libmongoc does | a server must not make one `executeBulkWriteCommand()` loop or grow its results without bound | `cargo test cursor_result_bound`, `cargo test result_index_out_of_range` |
| TLS keys among the driver options other than `ca_dir` and `crl_file` (ext-mongodb 1.x's `pem_file`, `pem_pwd`, `ca_file`, `context`, `weak_cert_validation`, `allow_invalid_hostname`, `allow_self_signed`, and any `tls*`/`ssl*` key) | ignored: the connection runs without the TLS settings the application meant to give (unverified or in cleartext) | `InvalidArgumentException` "Unsupported driver option "<key>": TLS is configured with the URI options (tls, tlsCAFile, tlsCertificateKeyFile, ...) and the "ca_dir" and "crl_file" driver options" | TLS must never be weaker than asked for | `tests/local/manager-tls-001.phpt` |
| OCSP responses (stapled, or from the certificate's responder) | OpenSSL's `OCSP_basic_verify` with `OCSP_TRUSTOTHER` and the verified chain: a response signed by any certificate of that chain is trusted, the server's own certificate and the root included (a server whose key was stolen can vouch for its own revoked certificate); statuses from responses without `nextUpdate` stay cached for the life of the process; the cache has no size limit; every OCSP responder URL of the certificate is tried, 5 s each | the response must be signed by the certificate's issuer, or by a responder certificate included in the response that the issuer issued, with the OCSPSigning extended key usage and valid now (RFC 6960 4.2.2.2); a response without `nextUpdate` is checked but not cached; at most 1,024 statuses are cached (expired ones dropped first, then the oldest); at most 4 responder URLs are tried (5 s each, responses above 8 MiB refused as libmongoc does) | a compromised server key must not certify itself; revocation must not be hidden forever by a cache entry; bounded memory and handshake time | `cargo test --test ocsp` ("signed by the server certificate itself", "no nextUpdate"), `cargo test cache_rules` |
| Automatic encryption (`autoEncryption` driver option) without `bypassAutoEncryption` | encrypts with libmongocrypt, using query analysis from mongocryptd (spawned) or crypt_shared (dlopen), or, with `bypassQueryAnalysis`, Queryable Encryption's own rules | refused by the constructor (the client is not kept): `InvalidArgumentException` "Cannot enable automatic field-level encryption: ... is not supported by this build yet. Set \"bypassAutoEncryption\" for automatic decryption with explicit encryption." With `bypassAutoEncryption` the option works as in the reference (every option check and message; replies are decrypted automatically). Before CSFLE support, `autoEncryption` was ignored, i.e. values meant to be encrypted would have been written in clear | never write in clear what the application asked to encrypt; query analysis needs MongoDB Enterprise components (out of scope for now) | upstream `manager/manager-ctor-auto_encryption-001`, `-error-004`, `manager-getencryptedfieldsmap-001`, `cursor/bug1529-001` (they enable automatic encryption) |
| A `driver` driver option that is not an array | throws `InvalidArgumentException` "Expected "driver" driver option to be an array, ..." but still creates and stores the client (as for the other invalid `driver` values); the process then crashes at shutdown (SIGSEGV) | the same exception and the same stored client, no crash | crash | `tests/local/manager-options-typed-001.phpt` (the reference prints the same output, then crashes with exit status 139, which run-tests.php does not report) |
| Persistent clients after `fork()` | phongo resets them once per pid | kept, and reset by the same fork rule before their next I/O. `endSessions` is sent only by the process that created the client, never after a fork | same as above | `tests/local/manager-fork-001.phpt` |
| AWS KMS Encrypt request body | kms-message formats the master key's `key` into the JSON body unescaped (`"KeyId": "%s"`), so a key id holding `"` adds or replaces request fields | the key id is JSON-escaped; requests for every valid key id (ARNs, aliases) are byte-identical | when rewrapping, the KEK comes from a key vault document, which must not shape the signed request beyond its key id | `cargo test -p mongo-crypt` |
| Plaintext values in Queryable Encryption range errors | libmongocrypt prints the value being encrypted ("..., value: 98765"), the query bounds and their order-preserving encodings, and appends the whole `encryptExpression` input as Extended JSON | those values read `<redacted>`, also in the appended expression; the configured index bounds (rangeOpts min/max), operators, types and field names are kept | what the application asked to encrypt never reaches exception messages or logs | `tests/local/clientencryption-redact-001.phpt` |

## 2. Permanent, other

| Area | Reference | This driver | Why | Pinned by |
|---|---|---|---|---|
| `phpinfo()` rows `libmongoc SSL library`, `libmongoc crypto library`, `libmongocrypt crypto library` | `OpenSSL` / `libcrypto` (as built) | `rustls` / `RustCrypto` | the libraries really used (no C libraries) | none (no upstream test reads them) |
| Stack use of BSON encode/decode/JSON per nesting level | smaller frames: survives `fiber.stack_size=64K` at the deepest allowed nesting | larger frames: segfaults at 64 KiB fiber stacks at the deepest nesting, works at 128 KiB and with PHP's default 2 MiB | Rust frame sizes. The nesting limits themselves are identical ("Nesting level too deep") | none yet (follow-up: shrink the per-level frames) |
| APM delivery time | libmongoc calls the subscribers synchronously, from inside the operation (e.g. `commandStarted` before the command is sent) | events are queued and delivered, in the same order and with the same contents, when the operation releases the client: after server selection, and before the operation returns or throws | subscribers may call back into the driver while the client is borrowed (user decision: kept queued, not synchronous). Consequence: tools that time a command by the gap between the `commandStarted` and `commandSucceeded`/`commandFailed` callbacks (for example OpenTelemetry's MongoDB auto-instrumentation, which opens a span in `commandStarted`) get near-zero durations and shifted timestamps; the event's own `getDurationMicros()` is accurate. To time events anyway, each call carries one extra trailing argument where the method's signature accepts it: an `int`, the value `hrtime(true)` had when the event was created (nanoseconds, same clock; read it with `func_get_args()` or a trailing `mixed ...$extra`). It is passed when the method is a user function that declares exactly the interface's parameter, or ends in a by-value variadic parameter that is untyped, `mixed`, `int` or a union with `int`; methods with further (optional) parameters, a typed variadic of another type, or a by-reference variadic are called with the event only, as by the reference (never a `TypeError`, never a default replaced). The decision is taken once per subscriber, when it is registered; with no subscriber, no clock is read. PHPLIB's `RetryableWrites\Prose3_ReturnOriginalErrorTest` (it sets a fail point from `commandSucceeded`) cannot pass | the `apm/` PHPTs (order and contents), `tests/local/apm-hrtime-001.phpt` (the timestamp argument and the signatures that get it) |
| LogSubscriber delivery time | libmongoc calls `log()` synchronously, wherever the message is produced (also inside an operation) | messages reach the `mongodb.debug` stream at once; LogSubscriber instances get them, in order, when the operation releases the client (with the APM events: after the operation, before it returns or throws; at the end of the `Manager` constructor; at once for `mongoc_log()`). At most 10,000 messages wait for delivery. As for APM, `log()` gets one extra trailing `int` argument, `hrtime(true)` when the message was produced, under the same signature rules (exactly `log(int $level, string $domain, string $message)`, or a trailing variadic that accepts an int); other signatures get the three arguments only. The messages of a failing `Manager` constructor are delivered before its exception propagates (set aside while they run); when a subscriber throws then, its exception becomes the constructor exception's previous one, while the reference, which logs synchronously, sometimes throws only the subscriber's (for instance when an SRV lookup fails) | subscribers may call back into the driver while the client is borrowed (as for APM) | `tests/phpt/logging/` |
| TLS server checks that fail | single-threaded libmongoc reports most failed TLS handshakes during a server check as "connection closed" or "connection error" (the reason only in the host-name case: "TLS handshake failed: certificate verify failed (64): IP address mismatch") | "TLS handshake failed: <reason>" with OpenSSL's verify-error wording and numbers where one applies (20 unable to get local issuer certificate, 10 certificate has expired, 9 not yet valid, 23 certificate revoked, 3 unable to get certificate CRL, 62 hostname mismatch, 64 IP address mismatch), "TLS handshake failed: Cannot load Certificate Authorities from '<file>' and '<dir>'", "... Cannot find certificate in '<file>'", "... Cannot find private key in: '<file>'" (paths only, never the key password) | more useful; upstream `connect/standalone-ssl-verify_cert-error-003` expects "TLS handshake failed" | `tests/local/tls-verify-001.phpt` |
| TLS library and trust store | OpenSSL; without `tlsCAFile`/`ca_dir`, OpenSSL's default verify paths | rustls with the graviola crypto provider (Rust and assembly, constant-time; TLS 1.2 and 1.3; AES-GCM and ChaCha20-Poly1305; X25519, P-256, P-384; RSA, ECDSA and Ed25519 certificates). graviola needs AES-NI, PCLMULQDQ, AVX, AVX2, BMI1 and ADX on x86-64 (CPUs from about 2013 on) and NEON, AES, PMULL and SHA2 on arm64; on a CPU without them every TLS connection fails with "TLS handshake failed: TLS is not available on this CPU: the TLS library needs the ... instructions" (checked before graviola is used: never a crash). Valgrind does not emulate ADX, so TLS is unavailable under valgrind on x86-64. Without a CA option the system store is read as OpenSSL's default paths would find it: `SSL_CERT_FILE`/`SSL_CERT_DIR` when set, else the first existing bundle of the usual locations (`/etc/ssl/certs/ca-certificates.crt`, `/etc/pki/tls/certs/ca-bundle.crt`, ..., `/etc/ssl/cert.pem`); the macOS keychain is not consulted. `ca_dir` reads the hash-named files (`<hash>.<n>`) as OpenSSL does. Private keys: PKCS#8 (also PBES2-encrypted), PKCS#1 and SEC1, also with OpenSSL's legacy PEM encryption (AES-128/192/256-CBC, DES-EDE3-CBC). Key, certificate, CA and CRL files above 16 MiB are refused; at most 10,000 files of a `ca_dir` are read | no C libraries | `tests/local/tls-verify-001.phpt`, `cargo test --test tls`, `cargo test unsupported_cpu_is_an_error` |
| `crl_file` | OpenSSL `X509_V_FLAG_CRL_CHECK`: the server certificate's revocation is checked; a CA without a CRL in the file fails ("unable to get certificate CRL"); an expired CRL fails ("CRL has expired") | the same (webpki: end-entity revocation only, unknown status and expired CRLs are errors) | | `tests/local/tls-verify-001.phpt` |
