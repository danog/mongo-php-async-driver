# Divergences from ext-mongodb 2.5.6

This driver aims at exact parity with ext-mongodb 2.5.6 (libmongoc/libbson 2.5.8), with one rule
on top: **safety beats parity.** Where the reference would crash, read freed memory, overflow,
allocate without bound, leak a secret or let a server control something it should not, this
driver does the closest safe thing: it throws the nearest matching exception or refuses.

This file lists every difference that PHP code can observe: the reference behaviour, ours, and
the test that pins ours (PHPT under `tests/local/`, or a `cargo test`). Upstream tests that fail
because of an entry are named with it and listed in `tools/ci/expected-failures.txt`.

## 1. Safety

| Area | ext-mongodb 2.5.6 | This driver | Pinned by |
|---|---|---|---|
| `$doc[]['a'] = 1` on a `Document`/`PackedArray` | segfault (NULL offset in `read_dimension`) | `LogicException` "Cannot write to MongoDB\BSON\Document property", as for other writes | `tests/local/bson-null-offset-001.phpt` |
| `Int64 % -1` with `INT64_MIN` | SIGFPE on x86-64 (0 on arm64) | `Int64(0)`, as PHP's own `%` | `tests/local/bson-int64-mod-001.phpt` |
| Re-initialising a live `Document`/`PackedArray`/`Javascript` (e.g. a second `__unserialize()`) while iterators use the old bytes | the old buffer leaks | kept alive until the object is freed, then released: iterators never see freed memory | `tests/local/bson-reinit-001.phpt` |
| Arrays and objects changed or freed by user code while they are encoded to BSON (a `bsonSerialize()` or destructor reaching the container through a reference, an object handle or a declared property) | the hash table is walked through raw pointers: a table that grows, is rehashed or is freed meanwhile is read from freed memory; in-place changes of elements not yet reached are seen | each container is held while it is encoded (as PHP's `foreach` by value holds its array), so PHP separates it before changing it: arrays and dynamic properties are encoded as they were when their encoding started (later changes, additions and removals are not seen; a container freed meanwhile is still encoded), declared property values are read when reached | `tests/local/bson-encode-mutation-001.phpt` |
| A type map's `fieldPaths` changed or freed by the autoloader its class names run | the freed table is read on | the `fieldPaths` as they were when parsing started | `tests/local/bson-typemap-autoload-mutation-001.phpt` |
| A `Cursor` advanced, or its type map changed, by user code its own decoding runs (`bsonUnserialize()`, an autoloader) | the `getMore` frees the reply being decoded, which is read on | `next()`, `rewind()`, `toArray()` and `setTypeMap()` throw `LogicException` "The cursor cannot be advanced or changed while it decodes a document"; the document being decoded is finished normally | `tests/local/cursor-decode-reentrant-001.phpt` |
| A command over 2 GiB built from strings the driver appends itself (e.g. a huge key alt name) | libbson refuses the append; each call site reports it differently | `RuntimeException` (code 8) "attempted to send a "<command>" command of <n> bytes, which exceeds the maximum message size of 2147483647 bytes", before sending: a wrapped int32 length would make the server read the rest as further messages. Documents from PHP values over 2 GiB fail while encoding, as in the reference | `tests/local/bson-encode-max-document-001.phpt` |
| Reply sizes (`messageLength`, OP_COMPRESSED) | checked against the server's `maxMessageSizeBytes`; decompressed into a buffer of the declared size | the same checks and messages; the limit is bounded to 64 MiB, buffers grow at most 1 MiB per read, decompression stops one byte past the declared size, snappy/zstd headers that ask for more are refused | `cargo test net::`, `cargo test compress::` |
| Hosts discovered during a topology scan | every newly reported address joins the running scan: a server inventing hosts makes it endless | at most 100 discovered addresses join one scan (a replica set has at most 50 members); a failed server is re-checked at most once per address | `cargo test --test scan_bounds` |
| Secrets in `var_dump($manager)`, URI errors and logs | the URI with its password; option values in parser errors; logs print phongo's client hash (the URI's SHA-256 plus every option value) and, at TRACE level, hex dumps of every wire message | passwords, key passwords and secret `authMechanismProperties` read `******`; parser errors never quote secret values; the client hash in logs is an HMAC fingerprint under a per-process key; no TRACE output. The `speculativeAuthenticate` reply is hidden and auth commands are not monitored, as in libmongoc | `tests/local/manager-redact-001.phpt`, `tests/local/logging-redact-001.phpt` (the reference fails it) |
| Unescaped `@` in the userinfo (`mongodb://user:p@ss@host/`) | split at the first `@`: part of the password becomes a host name (sent to DNS, shown in errors) | `InvalidArgumentException` "... Password must not have unescaped chars. Percent-encode username and password according to RFC 3986." (libmongoc's message for the other unescaped characters) | `tests/local/manager-redact-001.phpt` |
| SCRAM iteration count from the server | any count ≥ 4096 (wraps above 2^31); an `i=` not starting with a digit reads an uninitialised pointer | 4096 to 10,000,000, else "SCRAM Failure: iterations must be at most 10000000"; a malformed `i=` is "SCRAM Failure: unable to parse iterations in sasl step2" | `cargo test step2_errors` |
| Reference cycles through subscribers (a subscriber keeping its `Manager`, or a `Server`/`Cursor`/`Session`/`WriteResult` of it) | never collected; with a `Cursor` inside, SIGSEGV at shutdown | reported to the GC and collected; no subscriber runs while the collector frees the cycle (its queued events are dropped) | `tests/local/manager-gc-cycle-001.phpt` (the reference fails it) |
| A non-array `driver` driver option | `InvalidArgumentException`, then SIGSEGV at shutdown | the same exception, no crash | `tests/local/manager-options-typed-001.phpt` |
| DNS answers for `mongodb+srv://` | libresolv's parser; the SRV port read without checking the record length; any number of records | a Rust parser with every bound checked (message ≤ 65,535 bytes, backward-only name pointers, records inside the message); "Invalid record in SRV answer for ..." for a short record, at most 1,024 records. On Unix only `/etc/resolv.conf` is read (no macOS scoped/VPN resolvers); Windows uses the system resolver, as libmongoc there | `cargo test dns::`, `cargo test srv::`, `cargo test resolv_conf` |
| `BulkWriteCommand` against a misbehaving server | `maxWriteBatchSize` ≤ 0 sends empty batches forever; the results cursor is followed without limit | at least one operation per batch; at most one result per operation and as many `getMore`s, else "bulk write returned more than N results for N operations" (the cursor is killed) | `cargo test batch_progress_with_zero_max_batch`, `cargo test cursor_result_bound` |
| ext-mongodb 1.x TLS driver options (`pem_file`, `ca_file`, `context`, `weak_cert_validation`, `allow_invalid_hostname`, any `tls*`/`ssl*` key) | ignored: the connection runs unverified or in cleartext | `InvalidArgumentException` "Unsupported driver option "<key>": TLS is configured with the URI options ..." | `tests/local/manager-tls-001.phpt` |
| OCSP | OpenSSL with `OCSP_TRUSTOTHER`: a response signed by any certificate of the chain is trusted (a stolen server key can vouch for itself); unbounded cache; statuses without `nextUpdate` cached forever; every responder URL tried | signed by the issuer or an issuer-delegated OCSP signer only (RFC 6960); at most 1,024 cached statuses, none without `nextUpdate`; at most 4 responders. Also: plain `http://` responders only (an `https://` one is skipped, i.e. soft-fail) and DER only | `cargo test --test ocsp`, `cargo test cache_rules` |
| KMS requests of client-side encryption | an AWS key id is formatted into the JSON body unescaped; one Azure/GCP token per provider, sent to whichever endpoint a key names; on-demand credential values formatted into request lines unchecked | key ids are JSON-escaped (byte-identical for every valid id); tokens are cached per provider and scope, so a key naming another domain gets its own; request paths with CR/LF are refused before sending | `cargo test -p mongo-crypt`, `cargo test -p mongo-core cloud_creds` |
| Plaintext in Queryable Encryption range errors | the value being encrypted, the query bounds and the whole `encryptExpression` appear in the message | they read `<redacted>`; index bounds, operators, types and field names are kept | `tests/local/clientencryption-redact-001.phpt` |
| `bypassQueryAnalysis` with cached `keyAltName` keys | the process aborts (libmongoc calls the absent mongocryptd client) | encrypted as without the cached keys | encryptedFieldsMap comparison with a keyAltName field |
| A `Cursor` or `Session` used by two fibers at once | n/a | the second use throws `LogicException` "The cursor is in use by another fiber" / "The session is in use by another fiber" before anything is sent | `tests/local/fiber-concurrency-001.phpt`, `tests/local/fiber-session-001.phpt` |
| A fiber wait interrupted by an exception or the fiber's destruction | n/a | the operation stops and its connection is closed, without marking the server Unknown or clearing its pool; what it held goes to the fibers waiting for it (its cluster at `maxPoolSize`, automatic encryption; a scan it ran is abandoned, and the fibers waiting for it select as after a scan that found nothing) | fiber probes, `tests/local/fiber-wait-interrupt-001.phpt`, `tests/local/fiber-autocrypt-wait-001.phpt` |
| A blocking `{main}` call while fibers are suspended in driver waits (one made where PHP forbids fiber switches, e.g. a tick function; elsewhere such a call waits through the loop, busy with the fibers' waits) | n/a | it never waits for what a suspended fiber holds (that fiber cannot run before the call ends: waiting would hang): with all `maxPoolSize` clusters in use it takes the client's spare cluster (kept for such calls and never given to a fiber, so fibers still run at most `maxPoolSize` operations; a second one needed at once lives for its operation only; in load-balanced mode a cursor or transaction it starts may continue on another connection and then fail); while the fibers' server scan runs it scans on its own (the fibers' scan still counts as running for other fibers); a `Cursor` or `Session` a fiber holds throws as above; automatic encryption held by a fiber (its key vault, collection-info or KMS I/O) throws `LogicException` "Automatic encryption is in use by another fiber" (code 0) before anything is sent. The fibers' sockets and their readiness are left alone: once the loop runs, the fibers go on with their replies | `tests/local/fiber-mixed-main-001.phpt`, `fiber-mixed-scan-001.phpt`, `fiber-mixed-pool-001.phpt`, `fiber-mixed-cursor-001.phpt`, `fiber-mixed-autocrypt-001.phpt`, `fiber-mixed-autoload-001.phpt` |

## 2. Other permanent differences

| Area | ext-mongodb 2.5.6 | This driver | Pinned by |
|---|---|---|---|
| Driver calls inside a `Fiber` | block the thread | every network wait, and the pause before an overload retry, suspends the fiber through `Revolt\EventLoop`. The extension registers the classes of revolt/event-loop 1.0.9 at MINIT (revolt-rs, compiled in; `ReflectionClass::getExtensionName()` is `mongodb`; one driver class, `Driver\NativeDriver`, instead of the library's `StreamSelectDriver`, `EvDriver`, `EventDriver` and `UvDriver`), unless another copy of revolt-rs (the `revolt` extension) did; either way there is one native loop per thread, and the driver's waits make no PHP calls: its sockets are sources of the loop's driver (registered edge-triggered in its poller, no Revolt callback per socket), with one unreferenced `delay()` for the earliest deadline. `EventLoop::setDriver()` throws `UnsupportedFeatureException` (revolt-rs never replaces the loop's `NativeDriver`). If the classes were registered first by a revolt-rs copy of an incompatible embedding ABI (an older `revolt` extension), the extension refuses to start: one `E_CORE_WARNING` names both ABIs, then PHP's "Unable to start mongodb module". In `{main}`, waits go through the loop once it is in use (`EventLoop` has a driver) and has something else to do (an enabled callback, referenced or not, something queued, or another wait of the driver), else they block as the reference (an idle loop: the same system calls, no deadline timer). Destructors, GC and shutdown never suspend. A wait whose reply is there when the loop next polls is not timed out, even when its deadline (`socketTimeoutMS`, `connectTimeoutMS`) passed while the loop could not run (a blocking `{main}` call, a long callback): the poll's events are taken before the timers run | `tests/local/fiber-*.phpt` (the native loop: `fiber-native-001.phpt`; the idle loop: `fiber-main-idle-001.phpt`; the refused driver swap: `fiber-set-driver-001.phpt`; deadlines: `fiber-mixed-timeout-001.phpt`; overload retries: `fiber-overload-backoff-001.phpt`; automatic encryption another fiber holds: `fiber-autocrypt-wait-001.phpt`); the incompatible `revolt` extension: `revolt-abi-mismatch-001.phpt` |
| Concurrent operations in fibers | n/a | libmongoc's pooled mode: each running operation has its own cluster, at most `maxPoolSize`; a fiber finding all in use waits at most `serverSelectionTimeoutMS` ("Timed out while checking out a connection from connection pool"); a call that cannot suspend never waits (see the blocking `{main}` call above). Clusters connect only to the selected server; scans run one at a time on the operation's fiber (no background heartbeats). A failed new connection has libmongoc's pooled errors and `SystemOverloadedError`/`RetryableError` labels, except that a host's addresses are tried happy-eyeballs style | `tests/local/fiber-pooled-001.phpt`, `tests/local/fiber-pooled-error-001.phpt`, `tests/local/fiber-mixed-pool-001.phpt` |
| APM and LogSubscriber delivery | synchronous, from inside the operation | queued and delivered in order when the operation releases the client (subscribers may call back into the driver). Timing tools that measure the gap between `commandStarted` and `commandSucceeded` get near-zero durations; `getDurationMicros()` is exact, and callbacks whose signature allows it get an extra trailing `int`, `hrtime(true)` when the event was created (README). At most 10,000 log messages wait | `apm/` PHPTs, `tests/local/apm-hrtime-001.phpt`, `tests/phpt/logging/` |
| Use after `fork()` | phongo resets a client at the child's first use: pre-fork cursors cannot advance, pooled sessions are dropped | no per-operation detection: a child keeps using its inherited connections and cursors; using them from both processes is the application's responsibility. The child's session pool starts empty, and a live cursor/session destroyed in the child sends nothing (fork counter, no system call). ObjectIds redraw their random part in each child (`pthread_atfork`, not a `getpid()` per id) | `tests/local/manager-fork-001.phpt`, `cargo test client_fork`, upstream `cursor/bug1274-*`, `session/bug1274-*` |
| TLS | OpenSSL; system roots from OpenSSL's default paths (Windows: the "root" and "CA" stores) | rustls with graviola (TLS 1.2/1.3). graviola needs AES-NI, PCLMULQDQ, AVX, AVX2, BMI1 and ADX on x86-64 (NEON, AES, PMULL, SHA2 on arm64): without them TLS connections fail with "TLS is not available on this CPU ...", never crash (so no TLS under valgrind on x86-64). Roots: `SSL_CERT_FILE`/`SSL_CERT_DIR`, else the usual bundle files (the macOS keychain is not read); on Windows, else the "root" store only (intermediates are not trust anchors). Files above 16 MiB and `ca_dir`s above 10,000 files are refused | `tests/local/tls-verify-001.phpt`, `cargo test --test tls` |
| TLS errors of server checks | mostly "connection closed" / "connection error" | "TLS handshake failed: <reason>" with OpenSSL's verify-error texts and numbers | `tests/local/tls-verify-001.phpt` |
| `phpinfo()` crypto rows | `OpenSSL` / `libcrypto` | `rustls` / `RustCrypto` | none |
| Wire compression | zlib, zstd (level 3), snappy C libraries | pure-Rust codecs, same negotiation; zstd at about level 1, so compressed sizes differ | `tests/local/compression-001.phpt` |
| Decimal128 range indexes | refused (ext-mongodb's libmongocrypt is built without them) | supported as libmongocrypt with Decimal128, verified against it; ext-mongodb can read such data but not run range queries on it | `tests/local/clientencryption-decimal128-range-001.phpt` |
| Error-message length | truncated at 503 bytes | not truncated (only very long host lists reach that) | none |
| BSON stack use | survives `fiber.stack_size=64K` at the deepest nesting | needs 128 KiB there (PHP's default is 2 MiB) | none |
| macOS: a server check whose reply arrives with the server's close | the check fails ("connection closed ...") | the reply is read first, as on Linux | `cargo test --test scan_parallel` |
| Supported builds | also debug and 32-bit PHP | NTS and ZTS, non-debug, 64-bit: Linux/macOS x86-64 and arm64, Windows x86-64 (nightly Rust); `build.rs` refuses the rest | `build.rs` |
| ZTS: persistent clients of threads still running at module shutdown | each thread's clients are destroyed at its GSHUTDOWN, also when the main thread runs it for a thread that is still registered (`mongoc_client_destroy` ends their pooled server sessions) | clients are per thread (as phongo's) and a thread's are destroyed at its own GSHUTDOWN (`ts_free_thread`: FrankenPHP and ext-parallel threads end that way); those of a thread that never ran it are dropped with the thread, their sockets closed without `endSessions` (the server expires the sessions) | none (needs threads that never end; the CI's ZTS jobs and its `frankenphp` job cover the per-thread clients) |

## 3. Not implemented yet

| Area | ext-mongodb 2.5.6 | This driver | Pinned by |
|---|---|---|---|
| GSSAPI, MONGODB-AWS and MONGODB-OIDC authentication | supported | fail closed: `AuthenticationException` "The <mechanism> authentication mechanism is not supported by this build yet" (never unauthenticated) | `tests/local/manager-auth-001.phpt` |
| Automatic encryption through query analysis (mongocryptd / crypt_shared, MongoDB Enterprise) | supported | `autoEncryption` without `bypassAutoEncryption`/`bypassQueryAnalysis` is refused: `InvalidArgumentException` "Cannot enable automatic field-level encryption: ..."; `cryptSharedVersion` in debug output is always `null`. Everything else of client-side encryption works as the reference | upstream `manager-ctor-auto_encryption-001`, `-error-004`, `manager-getencryptedfieldsmap-001`, `cursor/bug1529-001`; PHPLIB CSFLE spec tests |
